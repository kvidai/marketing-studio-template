# Video / Content Generation Rules

이 프로젝트를 클론한 **모든 사용자에게 공통 적용**되는 콘텐츠 생성 원칙. custom 은 베타,
검증된 설정은 `marketing-studio-template` 로 이식되어 불특정 다수가 클론해 쓴다.

## ⛔ 1. 독립 생성 — 기존 결과 재사용 금지 (CRITICAL)

새 영상/콘텐츠는 **이번 요청의 references + brief 만으로 독립적으로** 만든다.
**특별한 지시가 없는 한, 이전 캠페인의 결과(콘텐츠·문구·씬 구성·출력물·크롭 자산)를 참고하거나 첨부하지 않는다.**

**Why**: 만들다 좋은 결과가 나오면 그걸 **깨끗하게 템플릿화**해 재사용 자산으로 승격한다.
매번 기존 결과를 끌어다 섞으면 오염되어 깨끗한 결과를 분리할 수 없다.

| 허용 (결과물 아님) | 금지 (기존 결과) |
|---|---|
| 파이프라인 코드(video-template, cardnews 모드 등) | 이전 캠페인의 씬 콘텐츠·문구·완성 영상 |
| `references/brand/` 등 명시적 공용 입력 | 이전 캠페인의 크롭 자산·프리셋을 임의 재사용 |
| **폴더/파일 구조 관례** | 다른 family 의 **컴포넌트·스키마·모티프·애니메이션 코드 복제** |

## ⛔ 2. 코드 재사용 한도 = 폴더 구조까지만 (CRITICAL)

새 family(카드뉴스 톤 등)를 만들 때 기존 family 에서 가져올 수 있는 건 **폴더/파일 구조 관례뿐**이다.
스키마·모티프·씬 컴포넌트·애니메이션 로직을 복사해 리페인트하지 않는다 — 그건 "기존 결과 재사용"이다.

- 각 family 는 **처음부터** 설계한다. 그래야 진짜 좋은 결과가 나왔을 때 그것이 특정 파생본이 아니라
  독립 자산이라 깨끗이 템플릿화된다.
- "기존 X 를 템플릿 삼아 빠르게" 는 **유저가 명시적으로 지시할 때만**.

## 3. 템플릿화는 명시적 · custom→template 승격

- 결과를 재사용 자산(family/preset/skill)으로 **승격하는 것은 유저의 명시적 결정**. 내가 알아서 하지 않는다.
- custom 에서 검증된 좋은 설정만 `marketing-studio-template` 에 동일 적용한다(민감정보 제외).

## 애매하면
"기존 X 를 참고할까요?" 를 먼저 물어보고 진행한다. 짐작으로 재사용하지 않는다.
