<answer>
run-<name>은 Claude Code가 특별 취급하는 예약된 접두어가 아니라, 문서에 나온 /run-skill-generator가 자동 생성하는 스킬의 이름 규칙일 뿐입니다.

문서 원문:

▎ /run-skill-generator records the recipe instead... and commits it as a per-project skill at .claude/skills/run-<name>/. After that, /run, /verify, and any other agent in the repo follow the recorded recipe instead of rediscovering it.

풀어서 설명하면:

- <name> = 프로젝트/앱 이름이 들어가는 자리 (예: 이 저장소면 .claude/skills/run-marketing-studio/ 같은 식)
- /run, /verify는 원래 추론형입니다 — package.json, README, Makefile 등을 보고 어떻게 실행할지 매번 스스로 유추합니다. DB 연결, env 파일, 그래픽 세션, 멀티스텝 빌드처럼 표준 실행 방식을 벗어나면 이 추론이 자주 틀립니다.
- /run-skill-generator를 한 번 실행하면, 클린 환경에서 실제로 앱을 띄워보면서 "뭐가 통했는지"(설치 명령, env 변수, 실행 스크립트)를 기록해서 run-<name> 스킬로 저장합니다. 이후엔 /run이나 /verify, 그리고 저장소를 다루는 다른 에이전트들도 매번 추론하지 않고 이 기록된 레시피를 그대로 따릅니다.
- 그냥 일반 프로젝트 스킬이라 /run-<name>으로 직접 호출도 가능하고, .claude/skills/<name>/SKILL.md 규격을 그대로 따릅니다. run- 접두어 자체엔 별도 파싱 로직이 있는 게 아니라, 사람이 봐도 "이건 실행 레시피구나" 알아보기 쉽게 붙인 네이밍 컨벤션입니다.

이 리포에는 아직 .claude/skills/run-*가 없어서, 지금은 /run이 매번 package.json/README 기반으로 추론하는 상태입니다. /run-skill-generator를 한 번 돌려서 고정시켜두고 싶으면 말씀해주세요.
